# 💾 Database Structure & Example Data

## Firestore Collections Overview

### Collection: `admins`
**Purpose**: Store admin/user accounts

**Example Document**:
```json
{
  "email": "admin@company.com",
  "createdAt": "2026-01-15T10:30:00Z",
  "role": "admin"
}
```

**Document Structure**:
- **Document ID**: Firebase Auth UID
- **email** (string): Admin email
- **createdAt** (timestamp): Account creation time
- **role** (string): Always "admin"

---

### Collection: `employees`
**Purpose**: Store employee information and face data

**Example Document**:
```json
{
  "employeeId": "EMP001",
  "firstName": "Juan",
  "lastName": "Dela Cruz",
  "name": "Juan Dela Cruz",
  "email": "juan.delacruz@company.com",
  "department": "IT",
  "position": "Senior Developer",
  "status": "Active",
  "phone": "+63 9XX XXX XXXX",
  "photoUrl": "https://storage.googleapis.com/...",
  "faceDescriptor": [
    0.234, -0.156, 0.892, -0.567, 0.123,
    // ... 128 decimal values for face recognition
  ],
  "remarks": "Excellent employee, punctual",
  "createdAt": "2026-01-10T09:00:00Z",
  "registeredBy": "admin@company.com"
}
```

**Document Structure**:
- **Document ID**: Auto-generated by Firestore
- **employeeId** (string): Unique employee identifier
- **firstName** (string): Employee first name
- **lastName** (string): Employee last name
- **name** (string): Full name
- **email** (string): Employee email
- **department** (string): Department name
- **position** (string): Job position
- **status** (string): "Active", "Inactive", "On Leave"
- **phone** (string): Contact number
- **photoUrl** (string): URL to stored photo in Cloud Storage
- **faceDescriptor** (array): 128-element array of face recognition data
- **remarks** (string): Optional notes
- **createdAt** (timestamp): Registration date
- **registeredBy** (string): Admin email who registered

---

### Collection: `attendance`
**Purpose**: Store daily attendance records

**Example Document**:
```json
{
  "employeeId": "EMP001",
  "name": "Juan Dela Cruz",
  "department": "IT",
  "position": "Senior Developer",
  "date": "2026-08-12",
  "dayOfWeek": "Tuesday",
  "timeIn": "08:01 AM",
  "timeOut": "05:02 PM",
  "totalHours": 9.01,
  "status": "Present",
  "remarks": "Regular attendance",
  "late": false,
  "undertime": 0,
  "overtime": 60,
  "createdAt": "2026-08-12T08:01:00Z",
  "faceMatchConfidence": 95.5
}
```

**Document Structure**:
- **Document ID**: Auto-generated by Firestore
- **employeeId** (string): Employee reference
- **name** (string): Employee name
- **department** (string): Department
- **position** (string): Job position
- **date** (string): Attendance date (YYYY-MM-DD)
- **dayOfWeek** (string): Day name
- **timeIn** (string): Time In (HH:MM AM/PM)
- **timeOut** (string): Time Out (HH:MM AM/PM)
- **totalHours** (number): Hours worked
- **status** (string): Attendance status
- **remarks** (string): Automatic or manual remarks
- **late** (boolean): Is employee late?
- **undertime** (number): Minutes short
- **overtime** (number): Minutes over
- **createdAt** (timestamp): Record creation time
- **faceMatchConfidence** (number): Face recognition accuracy %

---

## Possible Status Values

### Attendance Status Types

1. **Present** - Employee came and left normally
2. **Late** - Employee came after 9:00 AM
3. **Absent** - No record for the day
4. **On Leave** - Employee is on approved leave
5. **Work From Home** - Remote work status
6. **Incomplete** - Only Time In, no Time Out
7. **Error** - Data issue or system error

---

## Remarks Examples

### Automatic Remarks Generated by System

- "Time In - Dumating na" → Employee arrived
- "Time Out - Umalis na. Kabuuang oras: 9.0 hours" → Employee left
- "Late - 15 minutes late" → Late by 15 minutes
- "Hindi nakilala ang mukha - Face not recognized" → Face not in system
- "Hindi Nakarehistrong Empleyado" → Employee doesn't exist
- "Nakapag-Time In na" → Can't time in twice
- "Walang Time In" → Can't time out without time in

## Query Examples

### Find all employees in IT department
```
employees
  .where("department", "==", "IT")
  .get()
```

### Get today's attendance
```
attendance
  .where("date", "==", "2026-08-12")
  .orderBy("timeIn")
  .get()
```

### Find late employees for a date
```
attendance
  .where("date", "==", "2026-08-12")
  .where("status", "==", "Late")
  .get()
```

### Get attendance for specific employee in date range
```
attendance
  .where("employeeId", "==", "EMP001")
  .where("date", ">=", "2026-08-01")
  .where("date", "<=", "2026-08-31")
  .orderBy("date")
  .get()
```

### Storage Requirements

| Item | Size |
|------|------|

- **For 100 employees**: ~500 MB for photos, ~10K attendance records/month

## Backup Strategy

### Recommended Backup Schedule

1. **Daily**: Export attendance records to CSV
2. **Weekly**: Export employee database
3. **Monthly**: Full Firestore export (Firebase provides this)

### How to Export from Firebase

1. Go to **Firestore Database**
2. Click **⋮ (menu)** → **Manage** → **Export collection**
3. Choose storage location
4. Download when ready

---

## Data Retention Policy

### Recommended Retention

- **Attendance Records**: 3-7 years (compliance requirement)
- **Employee Records**: Keep until 1 year after separation
- **Photos**: 1 year after employee exit
- **Face Descriptors**: Delete if employee exits

### How to Archive

1. Export old records to CSV
2. Store in archive Cloud Storage bucket
3. Delete from Firestore after confirmation

## Troubleshooting Data Issues

### No Face Detected in Photo
**Cause**: Photo quality issue
**Solution**: Re-register with clearer photo

### Duplicate Employee Records
**Cause**: Registered twice
**Solution**: Delete duplicate, update attendance references

### Attendance Record Errors
**Cause**: Manual entry mistakes
**Solution**: Use edit function in Attendance Records page

### Face Recognition Failures
**Cause**: Poor face quality or lighting
**Solution**: Re-capture in better conditions
